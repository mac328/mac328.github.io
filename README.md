# mac328.github.io

`https://mac328.github.io/`（ドメインの一番上）を配信するリポジトリ。

**ここに置くのは 328 Studio 全体のもの**だけ。アプリ固有のものは、
そのアプリのリポジトリ（例: `mac328/eiken-dojo` → `/eiken-dojo/`）に置く。

| 置き場所 | 何を置くか | 例 |
|---|---|---|
| ここ（トップ） | 提供者ぜんたいのもの | `app-ads.txt`、328 Studio の案内 |
| `/eiken-dojo/` | 反復トレのもの | Web版、プライバシーポリシー |

## app-ads.txt

AdMob の承認を受けるために要る。中身は AdMob **アカウント**の ID
（`pub-4259051521565413`）で、アプリ名もパッケージ名も入らない。
つまり最初からアプリ単位ではなく提供者単位のもの。だからトップに置く。

```
google.com, pub-4259051521565413, DIRECT, f08c47fec0942fa0
```

**なぜドメインの一番上でないといけないか**

広告枠のなりすまし対策の規格（IAB）で、買い手のプログラムが自動で
取りに来る。人に URL を教える手段がないので、置き場所が固定されている。

- 読まれる: `https://mac328.github.io/app-ads.txt`
- 読まれない: `https://mac328.github.io/eiken-dojo/app-ads.txt`

取りに来る先のドメインは、**Play ストアの掲載情報の「ウェブサイト」欄**から
決まる。そのため次の2つがそろって初めて確認が通る。

1. Play Console → ストアの設定 → ストアの掲載情報に表示する連絡先の詳細 →
   ウェブサイトに `https://mac328.github.io/` を登録
2. このリポジトリに `app-ads.txt` を置く

そのあと AdMob → アプリの設定 → **Verify app**。
クローラが来るまで最大24時間。「アプリの確認」が**確認済み**になれば成功で、
承認状況が「要審査」から先へ進める（未承認のあいだは広告の配信が制限される）。

## index.html

ストアの「ウェブサイト」から来た人の行き止まりを作らないための案内ページ。

**Web版へのリンクは貼らない。** アプリ版には広告があり、Web版には無いので、
ストアからWeb版へ誘導すると収益が立たなくなるため。リンクを知っている人が
たどり着くぶんは構わない、という整理。

アプリが増えたら「提供中のアプリ」に並べる。
